# v0.19.2 server 자동 합류와 BFT 로그 개선

## 요청

- 배포 파일에서 `./ieum-chain server`만 실행해 노드가 작동할 것
- 제네시스 서버 4대가 연결되면 공통 검증자 집합으로 BFT 합의를 시작할 것
- BFT 라운드 제한 시간 로그가 매번 새 줄을 만들지 않고 같은 줄의 숫자만 바뀔 것

## 처리

1. `server`의 기본 부트스트랩을
   `/dns4/node.ieum.aah.name/udp/7001/quic-v1/p2p/<운영 PeerId>`로 설정했습니다.
   운영 부트스트랩 서버 자신은 PeerId를 비교해 자기 자신에게 접속하지 않습니다.
2. 각 서버는 `validator_id + PeerId`를 로컬 검증자 개인키로 서명해 합의 topic으로
   2초마다 공지합니다.
3. 수신 노드는 Ed25519 서명과 PeerId 형식을 검증하고 공개키 순으로 정렬합니다.
4. 제네시스 높이에서 서로 다른 유효 검증자 4명이 모이면 네 노드가 같은 4명을
   선택하고 `config/validators.json`을 원자적으로 교체한 뒤 BFT 런타임을 시작합니다.
5. 제네시스 이후의 검증자 변경은 이 편의 경로로 처리하지 않습니다. 5번째 이후
   운영 후보는 선발 정책과 epoch 변경 절차를 사용해야 합니다.
6. 거래가 없는 유휴 상태에서는 합의 타임아웃을 발생시키지 않습니다. 실제 합의
   도중 타임아웃만 `\r`과 현재 줄 지우기를 이용해 한 줄에서 숫자를 갱신합니다.

- `cargo clippy --all-targets --all-features --locked -- -D warnings`
- 전체 단위·통합 테스트
- release 빌드

실제 4프로세스 QUIC 시험은 실행 환경의 소켓 생성 제한(`Operation not permitted`)으로
네트워크 단계가 차단됐습니다. 독립 폴더 네 곳의 키와 단일 검증자 설정 자동 생성까지는
확인했고, 네트워크 메시지·서명·동적 검증자 집합 코드는 컴파일 및 회귀 테스트로
검증했습니다.
