# v0.19.1 단일 제네시스 노드 부트스트랩

## 문제

전 세계에 IEUM 노드가 하나도 없는 최초 실행인데도 프로그램이 먼저 검증자 4명의
공개키를 모아 `config/validators.json`을 만들라고 중단했습니다. 첫 노드가 실행되지
않으므로 두 번째·세 번째 노드도 등록할 수 없는 순환 의존이었습니다.

## 변경

- `ieum-chain server` 최초 실행 시 검증자 키와 노드 키를 자동 생성합니다.
- 생성한 로컬 검증자 공개키 1개로 `config/validators.json`을 자동 생성합니다.
- 검증자 설정 로드와 합의 초기화가 1명부터 가능하도록 시작 조건을 변경했습니다.
- 4명 미만에서는 장애 허용 BFT가 아닌 부트스트랩 모드라는 안내를 로그에 남깁니다.
- 다음 epoch의 운영 검증자 세트는 기존과 같이 최소 4명을 요구합니다.

## 실행

```bash
./target/release/ieum-chain server
```

별도의 `validator-key create-config` 명령이나 다른 서버 3대의 공개키 사전 수집 없이
첫 서버가 실행되어야 합니다.

## 안전 범위

검증자 1명 상태는 네트워크 최초 구성과 개발을 위한 모드입니다. 이 상태는 단독
검증자가 멈추거나 잘못 행동할 때 이를 견디지 못합니다. 후보가 4명 이상 등록되고
동일한 다음 epoch 검증자 세트가 확정된 뒤부터 장애 허용 BFT 구성이 됩니다.

이번 변경은 첫 서버를 막던 순환 의존을 제거합니다. 원격 후보 등록 메시지의 P2P
수집과 다음 epoch 자동 반영은 v0.19.0 문서에 명시된 네트워크 결합 단계에서
완성해야 합니다.
