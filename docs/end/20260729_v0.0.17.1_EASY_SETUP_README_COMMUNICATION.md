# IEUM Chain v0.17.1 처리 기록

## 요청

- 서버별 개인키, 노드 키와 원장을 최초 실행 시 자동 생성
- 기존 설치의 키 유실 시 임의 재생성 방지
- 기존 README를 개발자 문서로 보존
- Ubuntu와 Windows 실행법을 초보자용 README로 작성
- peer 메시지, 화상채팅과 원격 도움 가능성 및 보안 검토

## 처리

- `server` 최초 실행에 안전한 설치 초기화 절차를 연결했습니다.
- `data/.ieum-initialized`로 신규 설치와 기존 운영 노드를 구분합니다.
- 최초 실행 시 `validator.key`, `server.node.key`, 원장 폴더와 빈 이벤트 설정을
  만들고 공개키와 PeerId를 출력합니다.
- 네 검증자 공개키를 담은 공통 `validators.json`이 없으면 합의를 시작하지 않습니다.
- 초기화 후 키 또는 원장이 없어지면 자동 재생성하지 않고 백업 복구를 요구합니다.
- 기존 `README.md`를 `README_DEV.md`로 이동하고 새 `README.md`를 초보자용으로
  작성했습니다.
- 통신 내용은 원장에 넣지 않고 E2EE, WebRTC, DID 상대 확인과 매 세션 승인을
  사용하는 별도 통신 계층 설계를 문서화했습니다.

## 보안 범위

`v0.17.1`에는 메시지, 영상 통화 또는 원격 제어 실행 코드를 넣지 않았습니다.
검증되지 않은 원격 제어를 체인 노드에 함께 넣으면 검증자 키와 사용자 자산이
노출될 위험이 크기 때문입니다. 먼저 1:1 E2EE 메시지부터 별도 버전으로 구현하고
감사한 뒤 화상과 제한된 원격 도움을 단계적으로 추가해야 합니다.
