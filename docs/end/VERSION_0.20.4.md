# IEUM Chain v0.20.4

## 요청

- GitHub 최신 소스를 기준으로 버전을 한 단계 올립니다.
- `127.0.0.1`, Docker `172.17.x.x`, VMware `192.168.153.x` 같은 주소가 외부
  피어의 재접속 후보로 잘못 사용되지 않게 합니다.
- 유선·Wi-Fi·에어포트·핫스팟·가상 어댑터가 함께 있는 환경에서도 현재 노드가
  공인 IP를 직접 보유하는지, NAT 내부인지, 실제 외부에서 접근 가능한지를 구분합니다.

## 처리

### 로컬 NIC와 외부 접근성 분리

운영체제 라우팅 표가 외부 통신에 선택하는 기본 로컬 IPv4를 확인합니다. 이 주소가
글로벌 주소이면 로컬 NIC 공인 IPv4로 표시하고, RFC1918·링크 로컬·CGNAT 주소이면
NAT 내부 노드로 표시합니다.

NIC에 공인 주소가 있어도 방화벽이나 UDP 7001 차단 때문에 외부에서 접근하지 못할 수
있습니다. 따라서 최종 판단은 독립된 외부 AutoNAT 서버의 역접속 결과로 구분합니다.

- `외부 직접 접근 가능`: 외부 역접속 성공
- `NAT/방화벽 내부`: 외부 역접속 실패가 누적되어 Private 확정
- `아직 확정할 수 없음`: 같은 공인 IP의 내부 VM만 있거나 독립 AutoNAT 서버가 없음

AutoNAT가 Private를 반환해도 판정 서버가 같은 공인 IP에 있으면 NAT loopback 문제일 수
있으므로 로그는 `외부 역접속 불가`로 표현하고 두 원인을 함께 안내합니다.

### 사설 주소 학습 정책

사설 IPv4는 주소 대역만 보고 같은 LAN이라고 가정하지 않습니다. mDNS에서 해당
PeerId를 실제로 발견한 경우에만 그 피어의 사설 주소를 허용합니다.

- 같은 LAN의 `192.168.1.x`: mDNS 발견 후 직접 연결 허용
- 다른 VMware/에어포트/핫스팟 사설망: 외부 Identify 주소로 받으면 제외
- `127.x`, `0.0.0.0`: 항상 제외
- 공인 IPv4와 bootstrap DNS: 직접 연결 후보로 유지
- CGNAT `100.64.0.0/10`: 공인 IP로 오판하지 않음

제외된 주소는 Kademlia 주소록에서도 제거하므로 공개 연결이 끊긴 뒤
`127.0.0.1`이나 Docker bridge로 재접속하는 현상을 방지합니다.

연결 피어가 0명이 되면 60초마다 학습 주소 대신 원본 bootstrap DNS를 다시 조회해
공개 노드로 자동 복구합니다.

## 검증

- 공인 IPv4, RFC1918, CGNAT, loopback 분류 단위 테스트
- 같은 LAN으로 mDNS 확인된 사설 주소만 허용하는 정책 테스트
- 기존 DNS bootstrap, QUIC, AutoNAT, relay, DCUtR 동작 유지

현재 Codex 작업 환경에는 Rust 도구체인이 없어 `cargo fmt/test/build`는 개발 서버에서
수행해야 합니다.
