# IEUM Chain v0.0.6.6 인스턴스·포트 충돌 및 외부 연결 보완

## 요청 사항

- 클라이언트 실행 시 이미 클라이언트 인스턴스가 실행 중인지 확인
- 운영 서버에서 서버와 클라이언트를 동시에 실행할 수 있도록 처리
- 인자 없는 실행은 계속 클라이언트 기본 실행으로 유지
- `server`만 지정하면 운영 서버 기본값을 사용
- 외부 PC의 클라이언트가 운영 서버에 자동 연결되는지 확인
- 빈 문자열 오류 대신 사용 중인 포트와 원인을 명확히 표시

## 처리 내용

### 1. 모드별 중복 인스턴스 확인

- 서버와 클라이언트에 서로 다른 localhost 전용 인스턴스 잠금을 적용
- 같은 장비에서 서버 1개와 클라이언트 1개는 동시에 실행 가능
- 같은 모드가 이미 실행 중이면 즉시 알아볼 수 있는 오류를 출력
- 잠금은 프로세스가 종료되면 운영체제가 자동으로 해제

### 2. 같은 장비의 포트 자동 분리

- 서버 기본값은 `P2P UDP 7001`, `RPC 127.0.0.1:8989` 유지
- 클라이언트는 기본 포트가 비어 있으면 `7001`, `8989` 사용
- 서버 등이 기본 포트를 사용 중이면 클라이언트가 다음 빈 포트를 자동 선택
  - 일반적인 서버 동시 실행 결과: P2P `7002`, RPC `8990`
- 클라이언트 원장은 서버와 겹치지 않게 `data/client-ledger` 사용
- 서버 원장은 기존 `data/ledger` 유지

### 3. 오류 메시지 개선

- 서버의 P2P 또는 RPC 포트가 사용 중이면 해당 프로토콜, 주소, 포트를 표시
- 클라이언트 자동 포트 범위에서 빈 포트를 찾지 못하면 검색 범위를 표시
- 기존의 `Error: ""`처럼 원인을 알 수 없는 종료를 방지

### 4. 외부 클라이언트 자동 연결 확인

- 인자 없는 클라이언트는 `config/bootstrap.json`을 자동으로 읽음
- 설정 파일이 없을 때는 내장된 운영 서버 주소를 사용
- 운영 서버 주소:

```text
/dns4/node.ieum.aah.name/udp/7001/quic-v1/p2p/12D3KooWAVRZjnbP8nXp8vD6irYFAXdLJVyczEFWdKLFzKnKDATx
```

- 시작 로그에 실제 자동 연결 대상, 선택된 P2P/RPC 포트, 원장 경로를 표시
- 서버의 `data/server.node.key`가 바뀌어 PeerId가 변경되면 위 주소도 갱신해야 함

## 실행 방법

운영 서버:

```bash
./target/release/ieum-chain server
```

일반 외부 PC:

```bash
./target/release/ieum-chain
```

같은 운영 서버에서 테스트 클라이언트도 실행:

```bash
# 첫 번째 터미널
./target/release/ieum-chain server

# 두 번째 터미널
./target/release/ieum-chain
```

두 번째 명령은 서버가 사용 중인 포트를 확인한 후 클라이언트 포트를 자동 변경한다.
