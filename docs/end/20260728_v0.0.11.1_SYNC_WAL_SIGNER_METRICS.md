# IEUM Chain v0.0.11.1 작업 기록

## 목적

0.10.1에서 만든 snapshot, embedded DB, 외부 signer 경계를 장기 실행에 필요한
재시도·복구·제한·관측 기반으로 강화한다.

## 처리

- `SnapshotScheduler`
  - 여러 피어에 누락 chunk를 round-robin으로 병렬 할당
  - 요청 timeout 시 실패 횟수를 기록하고 다른 피어로 재배정
  - chunk별 피어 재시도 상한과 전체 in-flight 상한
- `EmbeddedDb`
  - commit image를 WAL에 먼저 fsync
  - WAL을 본 DB 파일로 checkpoint하고 디렉터리 fsync
  - 시작 시 남아 있는 WAL을 우선 읽어 crash 직전 commit 복구
- `ExternalSigner`
  - 응답 제한시간과 최소 호출 간격
  - 우선순위가 있는 여러 signer command failover
  - 모든 응답의 Ed25519 서명 재검증 유지
- `NodeMetrics`
  - 확정 높이, 피어 수, 동기화 목표, 합의 라운드
  - signer 실패, snapshot 재시도 누계
  - Prometheus text exposition 형식 출력

## 호환성

- 체인 ID, 블록, transaction, finality certificate 형식은 바뀌지 않는다.
- 기존 `ieum-state.db`는 그대로 읽는다.
- SQL 변경은 없다.

## 남은 작업

이번 버전은 네트워크 wire format 변경을 동시에 넣지 않았다. 다음 버전에서 nil
proposal/vote와 round-change certificate를 메시지 버전 `/3`으로 결합하고,
metrics HTTP endpoint 및 Grafana dashboard를 추가한다.

메인넷 DB는 운영 데이터 규모와 장애 복구 시험 뒤 RocksDB 또는 SQLite 중 하나를
선택하고 migration 도구와 함께 도입해야 한다.
