# v0.0.16.1 재단 수수료 운영 문서

## 1. 적용 정책

- 검증자(블록 생성자): 거래 수수료의 80%
- 재단: 거래 수수료의 20%
- 소각: 0%
- 재단 주소: `0x356456fF1216B57a6f8891B195b42d296789B67D`
- 체인 내부 정규화 주소: `0x356456ff1216b57a6f8891b195b42d296789b67d`

재단 몫은 `fee * 2000 / 10000`으로 내림 계산합니다. 계산 후 남은 수수료
전부를 검증자에게 지급하므로 분배 합계는 항상 원래 수수료와 같습니다.

예:

| 원래 수수료 | 검증자 | 재단 | 소각 |
|---:|---:|---:|---:|
| 100 | 80 | 20 | 0 |
| 3 | 3 | 0 | 0 |

## 2. 코드와 키의 역할

재단 주소와 비율은 모든 노드가 같은 결과를 계산하도록 합의 코드
`src/chain.rs`에 고정되어 있습니다.

`config/validator.key`에는 재단 주소를 넣지 않습니다. 이 파일에는 검증자가
BFT 합의 메시지를 서명하는 Ed25519 개인 seed 32바이트 hex만 들어갑니다.
재단 주소는 일반 AAH 계정 주소이며 검증자 개인키와 관계가 없습니다.

## 3. 블록 처리 흐름

확정된 블록을 상태에 적용할 때 각 거래마다 다음 순서로 처리합니다.

1. 송신자에게서 송금액과 수수료를 차감합니다.
2. 수신자에게 송금액을 적립합니다.
3. 수수료의 80%와 반올림 나머지를 블록 생성자에게 적립합니다.
4. 수수료의 20%를 재단 주소에 적립합니다.
5. nonce를 증가시킵니다.

후보 블록이나 미확정 투표 단계에서는 잔액을 적립하지 않습니다.

## 4. 배포 전 중요 조건

이 버전은 잔액과 state root를 바꾸는 합의 변경입니다. 서로 다른 버전의
검증자가 섞이면 같은 블록으로 서로 다른 상태를 계산할 수 있습니다.

- 모든 검증자와 상태 검증 노드를 같은 시점에 `v0.16.1`로 올립니다.
- 현재 운영 체인에 이미 확정 거래 블록이 있다면 바로 적용하지 않습니다.
  이 구현은 높이 1부터 새 정책으로 재계산하므로 기존 원장 재생 결과가 바뀝니다.
- 아직 운영 거래 블록이 없는 신규 체인 또는 테스트넷에서 적용합니다.
- 기존 운영 원장을 유지해야 한다면 별도의 활성화 높이와 상태 마이그레이션을
  구현한 후 배포해야 합니다.

버전 확인:


예상 버전은 `ieum-chain 0.16.1`입니다.

## 6. 운영 배포 순서

1. 모든 검증자 노드를 중지합니다.
2. 데이터와 설정을 백업합니다.
3. 동일한 커밋의 `v0.16.1` 바이너리를 모든 검증자에 배포합니다.
4. `config/validator.key`와 검증자 공개키 설정이 서로 일치하는지 확인합니다.
5. 검증자 노드를 재시작합니다.
6. 블록 확정, state root 일치, 재단 잔액을 확인합니다.

예시:

```bash
cp -a data "data_backup_before_v0.16.1_$(date +%Y%m%d_%H%M%S)"
sudo systemctl restart ieum-chain
sudo systemctl status ieum-chain --no-pager
sudo journalctl -u ieum-chain -n 100 --no-pager
```

실제 systemd 서비스 이름이 다르면 등록된 서비스명을 사용합니다.

## 7. 재단 적립 확인

JSON-RPC가 `127.0.0.1:8989`에서 실행 중인 경우:

```bash
curl -s http://127.0.0.1:8989 \
  -H 'content-type: application/json' \
  --data '{"jsonrpc":"2.0","id":1,"method":"eth_getBalance","params":["0x356456fF1216B57a6f8891B195b42d296789B67D","latest"]}'
```

수수료가 있는 거래가 포함된 블록이 확정된 뒤 잔액이 증가해야 합니다.
표시값은 Ethereum JSON-RPC 규격에 따른 16진수 최소 단위입니다.

## 8. 장애 시 확인

- 검증자별 블록 높이와 state root가 같은지 확인합니다.
- 일부 노드가 `v0.15.2` 이하이면 즉시 중지하고 버전을 통일합니다.
- 재단 잔액이 늘지 않으면 거래 수수료가 0이 아닌지와 블록 확정 여부를 확인합니다.
- `validator.key`에는 주소가 아닌 Ed25519 개인 seed가 들어 있는지 확인합니다.
- 원장 불일치 시 새 블록 생성을 중지하고 배포 전 백업으로 복구합니다.
