# IEUM Chain v0.20.9 사고 복구 원칙

## 핵심 원칙

> 거래 단위 복구: 해킹·오발행처럼 영향 거래가 명확할 때 사용  
> 체크포인트 롤백: 원장 전체가 손상되거나 합의 버그가 발생했을 때만 사용

사용자가 많아진 운영 체인에서 일부 거래 때문에 전체 원장을 과거로 되돌리면 사고와
무관한 정상 거래까지 취소되어 큰 혼란이 생깁니다. 따라서 IEUM Chain은 거래 단위
복구를 기본으로 하고 체크포인트 롤백을 최후 수단으로 둡니다.

## 거래 단위 복구

확정된 블록이나 거래를 삭제하지 않습니다. 원본 거래 이력을 보존한 채 새 블록에
사고 ID, 원본 거래 해시, 피해 대상, 금액과 승인 정보를 가진 보상 기록을 남기는
방식으로 처리합니다. 현재 체인의 `IncidentCompensation` 시스템 이벤트가 이 원칙에
맞는 기반 경로이며 재단 보유 잔액 안에서만 실행되어 총공급량을 임의로 늘리지 않습니다.

강제 차감, 자산 동결과 후속 주소 추적은 오판 시 정상 사용자의 재산을 침해할 수
있으므로 검증자 다중서명, 만료시간, 중복 실행 방지와 감사 기록이 완성되기 전에는
활성화하지 않습니다.

## 체크포인트 롤백

체크포인트 롤백은 원장 전체 손상, 합의 구현 오류 또는 모든 노드가 동일한 잘못된
상태를 확정한 경우에만 사용합니다. 적용 전 서비스 중지, 각 노드 전체 백업, 대상
높이와 블록 해시 비교, 검증자 합의가 필요합니다. 단일 노드나 단일 관리자의 임의
롤백은 허용하지 않습니다.

## 복구 승인 기준

거래 단위 복구와 체크포인트 롤백 모두 다음 조건 중 하나를 충족해야 합니다.

- 등록 검증자 수의 3/4 이상 승인
- 전체 검증자 투표권(보유량·스테이크 가중치)의 3/4 이상 승인

동일 검증자의 중복 승인은 한 번만 계산하며 미등록 검증자의 승인이 하나라도 섞이면
계획 검증을 거부합니다. 승인 대상은 설명 문자열이 아니라 체인 ID, 사고 ID, 복구
종류, 원본 거래 또는 체크포인트, 만료 시각을 포함한 복구 계획의 정확한 해시여야 합니다.

## 운영 확인

```bash
./ieum-chain recovery policy
```

이 명령은 원장을 변경하지 않고 현재 복구 원칙만 출력합니다.
