# IEUM Chain v0.15.2 실제 SQLite 저장 엔진

## 목적

v0.15.1까지 사용하던 `EmbeddedDb`는 모든 key-value를 JSON 한 파일로 직렬화한
뒤 파일 전체를 교체하는 과도기 구현이었다. v0.15.2에서는 공개 API를 유지하면서
실제 SQLite 저장 엔진으로 교체한다.

## 적용 내용

- DB 파일: `<data-dir>/db/ieum-state.sqlite3`
- journal: SQLite WAL
- durability: `PRAGMA synchronous=FULL`
- 동시 접근 대기: `PRAGMA busy_timeout=5000`
- write: `BEGIN IMMEDIATE`와 prepared statement를 이용한 원자적 batch
- key: UTF-8 `TEXT PRIMARY KEY`
- value: 임의 바이트 `BLOB`
- metadata: schema version과 commit generation
- prefix scan: 정렬된 key 범위 조회
- backup: WAL checkpoint 후 단일 SQLite DB 파일 복사

Rust crate를 추가하지 않고 운영체제의 `libsqlite3` ABI를 연결하므로 기존
`Cargo.lock`과 `--locked` CI를 유지한다. Ubuntu에서는 다음 런타임 패키지가
필요하다.

```bash
sudo apt update
sudo apt install -y libsqlite3-0
```

컴파일 링크 파일을 찾지 못하는 환경에서는 개발 패키지도 설치한다.

```bash
sudo apt install -y libsqlite3-dev
```

## v0.15.1 데이터 자동 이관

새 SQLite 파일이 아직 없고 아래 파일이 있으면 최초 `EmbeddedDb::open`에서
자동 이관한다.

```text
<data-dir>/db/ieum-state.db
```

이관이 성공한 뒤 원본은 삭제하지 않고 다음 이름으로 변경한다.

```text
<data-dir>/db/ieum-state.legacy-v1.json
```

이관 도중 오류가 나면 transaction을 rollback하고 기존 파일을 그대로 둔다.
운영 적용 전에 데이터 디렉터리 전체 백업을 별도로 보관한다.

## 운영 적용

```bash
cargo fmt --all --check
cargo clippy --all-targets --all-features --locked -- -D warnings
cargo test --all-targets --all-features --locked
cargo build --release --locked
```

노드를 한 번 시작한 뒤 다음 파일을 확인한다.

```bash
ls -lh data/ledger/db/ieum-state*
```

정상 이관 후에는 `ieum-state.sqlite3`와 기존 데이터 백업
`ieum-state.legacy-v1.json`이 보인다. 서버와 client의 `--rpc-data-dir`이
다르면 각 데이터 디렉터리에서 독립적으로 이관된다.

## RocksDB 판단

v0.15.2 기본 구현은 SQLite 하나로 고정한다. 동일 데이터에 SQLite와 RocksDB를
동시에 쓰면 장애 복구 시 어느 쪽이 원본인지 불명확해지기 때문이다.

실제 블록 처리량과 DB write latency를 측정해 SQLite가 병목으로 확인될 때만
검증자 전용 RocksDB backend를 별도 버전에서 추가한다. 그때는 backend별 DB
디렉터리, 명시적 export/import 도구, 동일 state root 대조 시험을 먼저 마련한다.
