# v0.0.16.2 운영 검증자 키 구성

## 1. 목적

운영 검증자 개인키를 안전하게 생성하고, 개인키를 이동하거나 출력하지 않은 채
공개키만 모아 모든 노드가 공유할 `config/validators.json`을 생성합니다.

- `validator.key`: 각 검증자 서버에만 보관하는 Ed25519 개인 seed
- `validators.json`: 검증자 공개키와 투표권 목록. 모든 검증자 서버가 동일하게 사용
- 재단 수수료 주소: 위 두 파일과 무관하며 `v0.16.1` 합의 코드에 고정

## 2. 빌드 및 버전 확인

```bash
cargo fmt --all &&
cargo fmt --all --check &&
cargo clippy --all-targets --all-features --locked -- -D warnings &&
cargo test --all-targets --all-features --locked &&
cargo build --release --locked &&
bash tests/four_process_network.sh target/release/ieum-chain

./target/release/ieum-chain --version
```

예상 버전은 `ieum-chain 0.16.2`입니다.

## 3. 검증자별 개인키 생성

검증자 1~4 서버에서 각각 한 번만 실행합니다.

```bash
cd /home/dev/www/ieum-chain
./target/release/ieum-chain validator-key generate \
  --output config/validator.key
```

명령은 기존 파일을 덮어쓰지 않습니다. Unix에서는 개인키 파일을 생성할 때부터
소유자만 읽고 쓸 수 있는 `0600` 권한을 적용합니다.

```bash
ls -l config/validator.key
wc -c config/validator.key
```

줄바꿈을 포함한 크기는 65바이트입니다. 파일 내용은 화면에 출력하거나 Git,
메신저, 이메일로 공유하지 않습니다.

## 4. 공개키 확인

각 서버에서 다음 명령을 실행해 출력된 64자리 공개키만 운영 담당자에게 전달합니다.

```bash
./target/release/ieum-chain validator-key public \
  --key config/validator.key
```

공개키는 검증자 순서와 함께 기록합니다.

```text
validator 1 = <PUBLIC_KEY_1>
validator 2 = <PUBLIC_KEY_2>
validator 3 = <PUBLIC_KEY_3>
validator 4 = <PUBLIC_KEY_4>
```

## 5. 운영 validators.json 생성

개인키 파일이 아니라 위에서 모은 공개키만 사용합니다.

```bash
./target/release/ieum-chain validator-key create-config \
  --public-key <PUBLIC_KEY_1> \
  --public-key <PUBLIC_KEY_2> \
  --public-key <PUBLIC_KEY_3> \
  --public-key <PUBLIC_KEY_4> \
  --voting-power 100 \
  --output config/validators.json
```

공개키가 4개 미만이거나 형식이 잘못됐거나 중복되면 파일을 만들지 않습니다.
기존 `validators.json`도 자동으로 덮어쓰지 않습니다.

생성한 파일의 해시를 기록하고 같은 파일을 모든 검증자 서버에 배포합니다.

```bash
sha256sum config/validators.json
```

모든 서버에서 SHA-256 값이 같아야 합니다.

## 6. 서비스 설정

각 서버는 자기 번호와 자기 개인키를 사용하되 `validators.json`은 동일해야 합니다.

```ini
ExecStart=/home/dev/www/ieum-chain/target/release/ieum-chain server \
  --port 7001 \
  --rpc-host 127.0.0.1 \
  --rpc-port 8989 \
  --rpc-data-dir /home/dev/www/ieum-chain/data/ledger \
  --node-key /home/dev/www/ieum-chain/data/server.node.key \
  --validator-index 1 \
  --validator-key /home/dev/www/ieum-chain/config/validator.key \
  --validators-config /home/dev/www/ieum-chain/config/validators.json \
  --sync-quorum-peers 2
```

검증자 2~4 서버는 `--validator-index`를 각각 2~4로 바꿉니다. 이 번호는
`create-config`에 공개키를 넣은 순서와 일치해야 합니다.

```bash
sudo systemctl daemon-reload
sudo systemctl restart ieum-chain
sudo systemctl status ieum-chain --no-pager -l
sudo journalctl -u ieum-chain -n 100 --no-pager
```

## 7. 운영 점검

```bash
./target/release/ieum-chain validator-key public \
  --key config/validator.key
sha256sum config/validators.json
ss -lunp | grep ':7001'
ss -ltnp | grep ':8989'
```

- 각 서버의 공개키가 `validators.json`의 해당 순번과 일치해야 합니다.
- 모든 서버의 `validators.json` SHA-256이 같아야 합니다.
- 개인키는 백업 매체에서도 암호화하여 보관합니다.
- 키를 분실하면 같은 검증자 신원을 복원할 수 없습니다.
- 키가 노출되면 해당 노드를 중지하고 검증자 집합 교체 절차를 진행합니다.
