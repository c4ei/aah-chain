# IEUM Chain v0.18.1 대상별 보안 통신 신호 직접 전달

## 확인한 다음 작업

v0.18.0은 WebRTC 협상용 암호문을 공용 Gossipsub topic에 발행한 뒤 수신 노드가
대상 PeerId를 확인했습니다. 암호문 평문은 노출되지 않지만 통화와 관계없는 구독
노드에도 envelope가 전달될 수 있어 메타데이터 노출 범위가 불필요하게 컸습니다.

## 변경 내용

- 공용 `ieum-chain/communication/1` Gossipsub 구독을 제거했습니다.
- `/ieum-chain/communication/1` request-response 프로토콜을 추가했습니다.
- 발신 노드는 envelope의 대상 PeerId를 파싱한 뒤 해당 피어에 직접 요청합니다.
- 수신 노드는 실제 연결 PeerId와 envelope 발신자를 다시 비교합니다.
- envelope 대상이 현재 노드인지, TTL과 암호문 크기·형식이 올바른지 기존 검증을
  그대로 수행합니다.
- 수신 노드는 메시지 ID와 수락 여부를 응답하며 거부·timeout·연결 실패를 로그로
  남깁니다.
- 발신자·대상 위조 거부 단위 테스트를 추가했습니다.

## 호환성과 운영

- 로컬 RPC 이름과 요청 형식은 변경하지 않았습니다.
- v0.18.0 노드는 공용 topic만 구독하므로 v0.18.1 노드와 통신 신호를 주고받을 수
  없습니다. 통신 기능을 사용하는 노드는 함께 업그레이드해야 합니다.
- 블록, 거래, 합의와 동기화 topic에는 변경이 없습니다.
- 영상·음성·SDP 평문은 체인과 상태 DB에 저장하지 않습니다.

## 보안 한계와 후속 작업

request-response는 통신과 관계없는 Gossipsub 구독자에게 envelope를 배포하지
않습니다. 하지만 직접 연결 상대와 네트워크 경로가 전송 시각·크기를 관찰할 수 있는
메타데이터 위험은 남습니다.

지갑의 WebRTC DTLS-SRTP, 통신용 E2EE 키, 안전번호, 카메라·마이크 권한 UX,
STUN/TURN 운영은 `ieum-wallet` 범위이며 별도 보안 감사를 거쳐야 합니다.
