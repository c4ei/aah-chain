# IEUM Chain v0.17.0 운영 문서

## 목적

거래가 있을 때만 블록을 생성하는 IEUM 구조에서도 날짜 기반 정책을 실행할 수 있게 하고,
일반 사용자 프로그램은 서명된 새 버전을 발견하면 설치 여부를 묻게 합니다.

## 배포 주의

`v0.17.0`은 블록과 합의 상태에 시스템 이벤트를 추가한 합의 변경입니다.
모든 검증자 노드를 같은 실행 파일과 동일한 `config/events.json`으로 교체해야 합니다.
검증자마다 설정이 다르면 해당 블록에 투표하지 않아 합의가 중단됩니다.

처음 배포할 때는 반드시 빈 설정을 사용합니다.

```json
{
  "events": []
}
```

네 검증자가 모두 v0.17.0으로 정상 동작하는 것을 확인한 뒤 이벤트를 등록하십시오.

## 시간 기반 이벤트

이벤트는 블록 높이가 아니라 UTC Unix 초인 `execute_at`으로 실행합니다.
거래가 없어도 실행 시각이 된 이벤트가 있으면 작은 시스템 체크포인트 블록을 제안합니다.
각 이벤트 ID는 상태 DB와 체크포인트에 기록되어 재시작·동기화 뒤에도 한 번만 실행됩니다.

```json
{
  "events": [
    {
      "id": "foundation-distribution-2027-01",
      "execute_at": 1798761600,
      "action": {
        "type": "treasury_distribution",
        "recipients": [
          {
            "address": "0x1111111111111111111111111111111111111111",
            "amount": 1000000000000000000
          }
        ]
      }
    }
  ]
}
```

지원 action:

- `treasury_distribution`: 재단 잔액을 여러 주소에 배분
- `periodic_producer_reward`: 지정된 생성자에게 주기 보상
- `incident_compensation`: 확정 원장을 삭제하지 않고 피해자에게 보상 역거래
- `protocol_checkpoint`: 자산 이동 없는 프로토콜 시간 기준점

주간 보상은 한 이벤트가 자동 반복되는 방식이 아니라, 실행 주차마다 고유 ID와 시각을 가진
이벤트를 미리 등록합니다. 이 방식이 재실행과 기간 계산의 모호함을 없앱니다.

재단 잔액보다 지급 합계가 크면 이벤트 블록은 거부됩니다. 이벤트를 이미 실행한 뒤
같은 ID를 다시 사용해도 거부됩니다.

## 이벤트 승인 절차

v0.17.0의 실행 계층은 승인된 이벤트 설정을 결정론적으로 집행합니다. 온체인 투표 UI와
제안 수집 RPC는 아직 포함하지 않습니다. 그 기능이 완성되기 전까지 다음 절차를 지킵니다.

1. 제안 문서에 이벤트 ID, 시각, 수령 주소, 금액, 근거를 기록합니다.
2. 검증자 정책에 따른 승인 결과를 별도로 보관합니다.
3. 승인된 JSON의 SHA-256을 네 검증자가 비교합니다.
4. 동일 파일을 모든 검증자 서버에 배포합니다.
5. 실행 시각 전에 모든 노드를 재시작하고 설정 로드 오류가 없는지 확인합니다.

```bash
sha256sum config/events.json
sudo systemctl restart ieum-chain
sudo journalctl -u ieum-chain -n 100 --no-pager
```

과거 블록 삭제·원장 재작성은 지원하지 않습니다. 사고 처리는 원 거래를 보존하고
`incident_compensation`으로 새 보상 기록을 추가합니다.

## 업데이트 확인

업데이트 manifest는 IEUM 릴리스 Ed25519 개인키로 서명하고, 노드에는 공개키만 배포합니다.
일반 PC 클라이언트는 시작할 때 manifest를 검사하고 새 버전이면 사용자에게 설치 여부를
묻습니다.

```bash
./target/release/ieum-chain client \
  --update-manifest-url https://releases.example.org/ieum/update-manifest.json \
  --release-public-key <32바이트_Ed25519_공개키_hex>
```

검증자 서버에도 같은 옵션을 줄 수 있지만 다운로드·교체하지 않고 알림만 표시합니다.
합의 변경은 모든 검증자의 배포 시점을 조정해야 하므로 의도된 동작입니다.

manifest의 서명 대상은 `signature`를 제외한 필드를 구조체 순서대로 JSON 직렬화한
바이트입니다.

```json
{
  "version": "0.17.1",
  "protocol_version": 2,
  "mandatory": false,
  "published_at": 1785283200,
  "notes": "보안 및 안정성 수정",
  "artifacts": {
    "linux-x86_64": {
      "url": "https://releases.example.org/ieum/ieum-chain",
      "sha256": "<sha256>"
    }
  },
  "signature": "<Ed25519_64바이트_서명_hex>"
}
```

업데이트는 HTTPS, manifest 서명, 실행 파일 SHA-256을 모두 통과해야 합니다. Linux에서는
기존 실행 파일을 `.previous`로 백업한 뒤 교체하고, 실패하면 기존 파일을 복구합니다.
Windows는 실행 중인 파일을 직접 교체할 수 없으므로 `.new.exe`로 준비하고 종료 후
교체합니다.
