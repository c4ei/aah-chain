# IEUM Chain v0.0.10.1

## 작업 목적

0.9.1의 네트워크 합의 안전성 다음 단계로 신규 노드의 대용량 상태 동기화,
복구 가능한 저장소, 다중 피어 검증, 운영 검증자 키 격리를 구현한다.

## 처리 내용

### 1. snapshot chunk와 다운로드 재개

- snapshot JSON을 zstd level 3으로 압축한다.
- 기본 512KiB 단위로 나눈다.
- manifest에 snapshot ID, height, block hash, state root, 전체 크기,
  chunk 수, 각 chunk SHA-256을 기록한다.
- 수신 chunk는 해시가 일치할 때만 디스크에 원자적으로 저장한다.
- `<data-dir>/sync/<snapshot-id>/resume.json`에 받은 chunk 번호를 저장한다.
- 프로세스가 중단돼도 같은 manifest를 받으면 누락 chunk만 이어받는다.
- 모든 chunk를 결합한 뒤 height/block hash/state root를 다시 검증한다.

### 2. 2~3개 피어 교차 검증

- sync 응답에 `height + block hash + state root`를 포함한다.
- 서로 다른 PeerId의 응답만 독립 표로 센다.
- 기본 quorum은 2개 피어이며 `--sync-quorum-peers 3`으로 높일 수 있다.
- 동일한 세 필드에 quorum이 모이기 전에는 확정 인증서를 적용하지 않는다.
- 동기화 완료 높이에서는 로컬 block hash/state root를 quorum 결과와 다시 비교한다.

검증자 4대 운영망에서는 가능한 경우 3개 피어 quorum으로 올리는 것이 권장된다.

### 3. embedded DB backend

- `<data-dir>/db/ieum-state.db`를 추가했다.
- canonical 상태, 높이 인덱스, transaction 위치 인덱스를 key-value로 저장한다.
- 전체 image를 임시 파일에 기록하고 fsync 후 rename해 중간 기록을 피한다.
- 재시작 시 embedded DB를 우선 canonical 상태로 복원한다.
- 0.9.x 도구와 rollback 호환을 위해 `canonical-state.json` mirror를 한 버전 유지한다.
- backend API를 분리했으므로 데이터가 커지면 RocksDB/SQLite로 교체할 수 있다.

현재 backend는 작은 테스트넷용 단일 writer 구현이다. 메인넷 규모에서는
페이지 단위 WAL과 online compaction이 있는 DB로 교체해야 한다.

### 4. 외부 signer/HSM

- `ValidatorSigner` 경계를 추가해 합의 코어가 개인키 저장 방식을 알지 못하게 했다.
- 로컬 키와 외부 signer 실행 파일을 모두 지원한다.
- 노드는 signer stdin으로 아래 JSON 한 건을 보낸다.

```json
{
  "version": 1,
  "public_key": "32-byte-ed25519-public-key-hex",
  "payload_hex": "bytes-to-sign-as-hex"
}
```

- signer는 stdout으로 64바이트 Ed25519 서명 hex만 반환한다.
- 노드는 반환 서명을 등록 공개키로 다시 검증하며 틀린 서명은 합의에 사용하지 않는다.
- stderr는 실패 원인으로만 처리하고 stdout에 로그를 섞으면 안 된다.

실행 예:

```bash
cargo run --release -- server \
  --validator-index 1 \
  --validator-signer-command /opt/ieum/bin/hsm-signer \
  --validator-public-key <ED25519_PUBLIC_KEY_HEX> \
  --validators-config config/validators.example.json
```

`hsm-signer`는 PKCS#11, Vault Transit 또는 cloud KMS에 연결하는 별도 adapter다.
IEUM 노드에는 PIN, HSM 세션키, 개인키를 전달하지 않는다.

## 데이터 변경

- SQL 변경 없음
- 신규 embedded 파일: `<data-dir>/db/ieum-state.db`
- 신규 snapshot 재개 파일: `<data-dir>/sync/<snapshot-id>/resume.json`
- 기존 원장과 finality certificate 형식은 변경하지 않음
- P2P sync message에 state root가 추가되므로 0.9.x와 mixed-version sync는 지원하지 않음

## 필수 확인

```bash
cargo fmt --all --check
cargo clippy --all-targets --all-features --locked -- -D warnings
cargo test --all-targets --all-features --locked
cargo build --release --locked
bash tests/four_process_network.sh target/release/ieum-chain
```

추가 운영 시험:

1. snapshot 중간에 프로세스를 종료한 뒤 누락 chunk만 받는지 확인
2. 변조 chunk가 거부되고 기존 정상 chunk는 유지되는지 확인
3. 한 피어가 거짓 state root를 보낼 때 quorum이 성립하지 않는지 확인
4. embedded DB 임시 파일만 남은 강제종료 후 이전 generation으로 복구되는지 확인
5. signer 종료·지연·잘못된 서명 때 노드가 블록에 서명하지 않는지 확인
