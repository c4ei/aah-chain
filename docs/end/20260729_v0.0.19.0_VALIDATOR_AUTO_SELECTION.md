# v0.19.0 검증자 자동 선발 기반

## 요청

- 프로그램과 CI가 사람의 `validators.json` 복사를 기다리지 않고 자동 실행될 것
- 운영 검증자를 쉽게 등록·검증할 것
- 유통량 1% 보유, 본인 국가의 IEUM 보유량 상위 50위, 관리자 승인 지원
- `node.ieum.aah.name`을 통한 자동 등록 방향 검토
- 이외의 안전한 선발·퇴출 조건 추가

## 처리

### 개발망과 CI

`--allow-insecure-test-keys`에서는 공개된 고정 테스트 seed 1~4로 공통
`validators.json`을 자동 생성합니다. 따라서 실제 4프로세스 CI가 최초 설치 단계에서
중단되지 않습니다. 운영 실행은 기존처럼 개인키와 공통 설정을 요구합니다.

### 운영 선발 정책

`ValidatorPolicy::select`는 확정된 원장 상태와 후보 목록을 사용해 다음 epoch 후보를
결정론적으로 계산합니다.

1. 보유량과 잠긴 위임 지분의 합이 확정 유통량 1% 이상
2. 국가 인증을 통과한 계좌를 국가별로 나눈 뒤 IEUM 보유량 상위 50위
3. 관리자 또는 거버넌스 승인

위 조건은 서로 대체 가능한 진입 경로입니다. 아래 보안·운영 조건은 모든 후보에게
공통으로 적용합니다.

- 지분 계좌가 검증자 공개키와 노드 주소 등록문에 전자서명
- 등록 창구에서 외부 UDP/QUIC 역접속 challenge 성공
- 첫 epoch 이후 최근 가동률 95% 이상
- 중복 검증자 키와 한 계좌의 다중 후보 등록 금지
- 차단된 후보는 다른 자격과 무관하게 제외
- 지분 순, 동일 지분이면 공개키 순으로 정렬하고 최대 50명 선발

위임 지분은 원장에 잠긴 수량만 인정합니다. 단순 잔액을 제3자가 대신 보유했다고
신고하는 방식은 인정하지 않습니다.

## node.ieum.aah.name의 역할

이 도메인은 검증자 자격 자체가 아니라 등록·발견 창구입니다. `ping`은 DNS와 ICMP만
확인하므로 UDP 7001의 QUIC 서비스, 개인키 소유권, 지분 계좌 소유권을 증명하지
못합니다.

최종 자동 등록 흐름은 다음과 같습니다.

1. 후보 노드가 기본 부트스트랩 주소로 접속
2. 서버가 일회용 nonce를 발급
3. 후보가 검증자 키와 지분 계좌 키로 등록문에 서명
4. 서버가 후보가 알린 UDP/QUIC 주소로 역접속
5. 유효한 등록을 네트워크에 전파하고 합의 블록에 포함
6. 모든 노드가 같은 정책으로 후보를 계산
7. 합의 안전을 위해 즉시가 아닌 다음 epoch 경계에서 validator set 반영

## 추가로 선택한 방식

- 잠긴 위임 지분: 1%를 혼자 보유하지 않아도 여러 사용자가 신뢰하는 노드 참여 가능
- 가동률 기준: 자산만 많고 실제로 블록을 검증하지 않는 노드 제외
- 소유권 이중 서명: 다른 사람의 계좌나 검증자 공개키를 도용한 등록 차단
- 외부 QUIC challenge: 사설 IP, 닫힌 포트, 허위 주소 등록 차단
- 차단 우선: 보안 사고·이중서명 노드는 관리자 승인이나 높은 지분으로 우회 불가

향후에는 동일 ASN/서브넷 검증자 수 제한, 이중서명 slashing, 위임 해제 대기기간,
관리자 1인 승인이 아닌 다중서명 거버넌스를 추가해야 합니다.
