# IEUM Chain v0.0.8.1

## 작업 목적

geth 비교표에서 중요도가 `최우선`, `높음`, `치명적`인 항목을 공개
테스트넷 이전에 필요한 실행 경로로 보강한다.

## 반영 내용

### 합의 실행·포크 처리

- RPC 거래는 mempool에만 들어가며 2/3 초과 precommit 뒤에만 반영한다.
- 인증서 서명, 투표권, 높이, 라운드, 블록 해시를 검증한다.
- 같은 높이의 다른 확정 해시를 감지하면 finality violation으로 중단한다.
- IEUM BFT는 확정 뒤 reorg를 허용하지 않는다. 인증서가 canonical을 결정한다.
- 고정 개발 검증자 키는 명시적 옵션 없이는 운영 실행에서 사용하지 않는다.

### 동기화

- 인증서를 최대 128개, 약 1.5MB 단위로 받는다.
- 연속 높이, 이전 해시, 거래 상태, 2/3 인증서를 검증한다.
- 현재 확정 높이 다음부터 이어받는다.
- 실제 현재/최고 높이를 `eth_syncing`으로 제공한다.
- 동기화 상태도 원장, 상태 저장소, 인증서 파일에 영속화한다.

### 상태 저장

- `state/canonical-state.json`에 확정 높이, 블록 해시, state root를 저장한다.
- 주소별 잔액·nonce, 높이→블록, 거래→블록/위치 인덱스를 저장한다.
- 임시 파일 작성 뒤 rename으로 원자적으로 교체한다.
- 기존 월별 99MB 활성 원장과 zstd 백업은 유지한다.

### 키 저장

- 사용자 secp256k1 개인키를 암호화 keystore로 저장한다.
- 반복 KDF, 난수 salt/nonce, 암호문 MAC 검증을 적용한다.
- 계정 생성·개인키 가져오기·니모닉 복원의 비밀번호가 실제 저장에 사용된다.
- 잠금 해제는 복호화와 주소 검증 성공 시에만 허용한다.
- 평문 개인키와 니모닉을 디스크에 저장하지 않는다.

주의: 자체 keystore v1은 공개 테스트넷용 1차 구현이다. 실제 자산을 다루기
전에 Argon2id/scrypt + AES-GCM 또는 Ethereum V3 keystore 전환, 외부 signer
또는 HSM 연동과 전문 보안 감사를 진행해야 한다.

### Mempool

- 기본 최대 10,000건, 16MiB
- 중복 거부, 수수료 우선 선택
- 동일 발신자/nonce 교체는 수수료 10% 이상 인상 필요
- 한도 초과 시 최저 수수료 거래부터 제거
- 합의 timeout 거래 재등록

### RPC·운영

- 실제 `net_peerCount`와 `eth_syncing`
- `eth_call`, `eth_getLogs`, uncle count 호환 응답
- 블록 거래 수와 블록 번호/인덱스 거래 조회
- `txpool_status`
- `ieum_nodeStatus`: 버전, 높이, tip, state root, 피어, mempool, sync, uptime

### 업그레이드

- `config/upgrades.json`에 높이 기반 프로토콜 일정을 둔다.
- 미지원 프로토콜 활성화 높이에 도달하면 제안 전에 중단한다.
- 같은 높이에 중복 업그레이드를 등록할 수 없다.

## 실행 변경

기존 고정 개발 키는 폐쇄형 개발망에서만 명시적으로 허용한다.

```bash
./target/release/ieum-chain server \
  --validator-index 1 \
  --allow-insecure-test-keys
```

운영 검증자는 `--validator-key` 파일에 32바이트 Ed25519 seed hex를 두고
파일 권한을 제한한다.

```bash
chmod 600 config/validator.key
./target/release/ieum-chain server \
  --validator-index 1 \
  --validator-key config/validator.key
```

## 실제 4대 서버 필수 시험

1. 같은 거래의 높이, 블록 해시, state root 일치
2. 검증자 1대 중단 상태에서 3대 확정 지속
3. 검증자 2대 중단 상태에서 확정 중단
4. 재시작 노드가 같은 tip까지 인증서 동기화
5. 같은 높이의 위조·상충 인증서 거부
6. timeout 뒤 거래 재제안과 유실 없음
7. keystore 오답 비밀번호와 변조 파일 거부
8. 강제 종료 중 상태 파일이 완전한 이전 또는 새 버전으로 복구
