# IEUM Chain v0.0.9.1

## 작업 목적

0.8.2에서 자동 빌드 검증 기반을 만든 뒤, 실제 네트워크 합의의 안전성과 장애 대응을 보강했다.

## 처리 내용

1. `locked_value`, `locked_round`, `valid_value`, `valid_round`를 합의 상태에 추가했다.
2. 2/3 초과 prevote를 관찰한 값만 lock/valid 값으로 기록한다.
3. 잠긴 노드는 같은 값 또는 자신이 확인한 valid round 조건을 만족하는 제안만 받아들인다.
4. proposal 서명 대상에 `valid_round`를 포함해 네트워크에서 변조할 수 없게 했다.
5. propose/prevote/precommit 제한 시간을 각각 설정할 수 있게 했다.
6. 단계가 바뀔 때 해당 단계의 deadline을 새로 계산한다.
7. 동일 검증자의 상충 서명 두 개를 `DoubleVoteEvidence`로 구성하고 양쪽 서명을 검증한다.
8. 증거를 `double-vote-evidence.jsonl`에 동기화 저장하며 재시작 뒤 중복 저장하지 않는다.
9. 검증된 증거를 consensus gossip topic으로 전파한다.
10. 같은 호스트에서 서로 다른 포트로 4개 검증자 프로세스를 실행할 수 있게 서버 중복 실행 guard를 조정했다.
11. 기본 개발망도 모든 프로세스가 같은 genesis/state root를 갖도록 공개 테스트 faucet을 결정론적으로 고정했다.
12. 네 개 QUIC 프로세스에 실제 거래를 넣고 높이와 state root 일치를 확인하는 CI 시험을 추가했다.

## 데이터 파일

- `<rpc-data-dir>/double-vote-evidence.jsonl`
- append-only JSON Lines
- 각 증거는 두 개의 완전한 서명 투표를 포함한다.
- 같은 검증자·높이·라운드·투표 단계 증거는 한 번만 저장한다.

## 실행 예

```bash
cargo run --release -- server \
  --validator-index 1 \
  --allow-insecure-test-keys \
  --port 7001 \
  --rpc-port 8989 \
  --rpc-data-dir data/node-1 \
  --propose-timeout-ms 3000 \
  --prevote-timeout-ms 2000 \
  --precommit-timeout-ms 2000
```

실제 네 프로세스 시험:

```bash
cargo build --release --locked
bash tests/four_process_network.sh target/release/ieum-chain
```

## 주의

- 고정 검증자 키와 결정론적 faucet은 폐쇄형 개발 테스트넷 전용이다.
- 공개망/메인넷에서는 명시적 genesis, 암호화 keystore, 외부 signer를 사용해야 한다.
- 이번 locked/valid 규칙은 IEUM의 단일 제안 블록 모델에 맞춘 최소 구현이다. nil proposal/vote와 라운드 인증서 압축은 후속 보강 대상이다.
- 이중투표 증거는 저장·전파까지 구현했으며 자동 slashing은 아직 실행하지 않는다.
