# AAH Chain 목표 구조

## 설계 원칙

| 영역 | 목표 |
|---|---|
| 합의 | 소수 검증자 기반 PoS/BFT |
| 블록 생성 | 거래가 있을 때 제안하고, 없으면 빈 블록을 생략 |
| 생존 확인 | 일정 시간마다 상태 루트를 담은 소형 서명 체크포인트 |
| 블록 제한 | 최대 거래 수와 최대 직렬화 바이트를 모두 제한 |
| 화폐 | 잔액, 송금, 수수료, 발행량, 스테이킹을 기본 모듈로 제공 |
| 신원 | DID와 VC, 발급기관·폐기 상태만 온체인 저장 |
| 프로그램 | 제한된 시스템 모듈 이후 WASM 실행 계층 추가 |
| 네트워크 | QUIC/libp2p, mDNS, DHT, bootstrap, relay |
| 데이터 | 상태 snapshot, pruning, archive node 분리 |
| 클라이언트 | PC 풀 노드, 필요할 때만 접속 가능한 모바일·웹 라이트 클라이언트 |

## 상시 접속 노드와 간헐 접속 클라이언트

- 검증자: 합의 참여를 위해 상시 접속
- 풀 노드·부트스트랩·RPC 노드: 네트워크 유지와 클라이언트 응답을 위해 상시 접속
- PC 지갑: 사용자가 선택하면 풀 노드, 기본값은 간헐 접속 클라이언트
- 모바일·웹 지갑: 실행할 때 연결하고 동기화·조회·전송 후 연결 종료

모바일은 전체 블록을 내려받지 않고 최신 확정 헤더, 검증자 집합, 필요한 계정의
Merkle proof만 받아 검증합니다. 자세한 흐름은 [CLIENT.md](CLIENT.md)에 정리했습니다.

## 이벤트 기반 블록

```text
유효 거래 도착 → mempool 검증 → 제안자 후보 블록 생성 → BFT 확정 → 상태 반영
거래 없음      → 블록 생략
체크포인트 시각 → height·마지막 블록 해시·상태 루트에 검증자 서명
```

체크포인트는 블록 높이를 증가시키지 않습니다. 시간 경과와 노드 생존 여부를
확인하고, 장기간 빈 구간 뒤에도 어떤 상태가 검증자 다수에게 관측됐는지 증명합니다.

## 피어 선택과 합의 참여의 분리

낮은 지연시간만으로 검증자를 고르면 Sybil/Eclipse 공격에 취약합니다.

- relay/RPC 선택: latency, uptime, reliability, 용량, 지역 다양성
- 합의 참여: stake, 검증 이력, epoch 규칙, slashing
- 연결 집합: 같은 IP 대역에 과도하게 몰리지 않도록 diversity 제한

IP와 상세 위치는 체인에 기록하지 않습니다. 노드 기능과 대략적인 지역,
서명된 성능 광고만 짧은 유효기간으로 공유하는 방향을 사용합니다.

## 신원 정보

주민번호, 신분증 이미지, 실명·주소 원문은 체인에 저장하지 않습니다.

1. 인증기관이 오프체인에서 사용자를 확인합니다.
2. 사용자 지갑에 서명된 VC를 발급합니다.
3. 체인에는 발급기관 DID와 자격증명 폐기 상태만 기록합니다.
4. 사용자는 필요한 속성만 선택적으로 제시합니다.

첫 구현은 서명된 VC와 status registry로 시작하고, 이후 선택 공개와
영지식증명을 별도 단계로 추가합니다.

## 프로그램 실행 순서

1. 코인 송금, 스테이킹, 멀티시그, 에스크로, 투표, VC 확인을 내장 모듈로 구현
2. 결정론적 실행과 CPU·메모리·저장공간 제한을 갖춘 WASM runtime 추가
3. 생태계 호환성이 실제로 필요할 때만 EVM 계층을 별도 검토

메인넷에서는 실행 결과의 결정론성, 상태 증가 비용, 업그레이드 방식이 합의
안전성과 직접 연결되므로 WASM을 네트워크 초기 단계에 함께 넣지 않습니다.
