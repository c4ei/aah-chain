# IEUM v0.19.8 트래픽 분산·중계 이벤트 보상 계획

## 목표

이음월렛과 일반 노드가 중앙 부트스트랩 서버에 계속 의존하지 않고 가까운 일반
노드로 연결되며, 연결 기회가 대형 노드에만 몰리지 않게 합니다. 유효한 거래·블록
동기화·통신 신호를 중계한 노드는 일~주 단위 이벤트 풀의 추첨 후보가 됩니다.

## 피어 선택

기본 12개 연결을 다음 세 종류로 나눕니다.

- 근거리 4개: RTT가 낮고 가동률이 기준 이상인 피어
- 다양성 4개: 아직 적게 선택된 국가와 ASN 우선
- 저부하 4개: 연결률이 낮은 하위 노드 우선

한 국가 3개, 한 ASN 2개, 중앙 부트스트랩 1개를 기본 상한으로 둡니다. 후보가
부족할 때만 국가·ASN 상한을 완화하며, 가동률과 부트스트랩 상한은 유지합니다.
국가 정보 하나만 신뢰하지 않고 지연시간, ASN, 가동률, 수용량을 같이 사용합니다.

국가별 보유량 순위는 검증자 후보 자격의 한 요소로 유지할 수 있지만, 일반 P2P
트래픽 분산의 직접 순위로 사용하지 않습니다. 그렇게 하면 국가 인증이 어려운
일반 사용자와 소형 노드가 영구적으로 배제될 수 있기 때문입니다.

## 중계 기여와 이벤트 풀

- 현재 재단 몫으로 들어오는 수수료 중 기본 25%를 이벤트 풀에 배정합니다.
- 기본 주기는 1일이며 운영 설정으로 최대 7일까지 늘릴 수 있습니다.
- 자기 확인 영수증은 거부하고 서로 다른 3개 피어가 확인한 노드만 후보가 됩니다.
- 같은 확인자·메시지 영수증은 한 번만 인정합니다.
- 확인자별 epoch당 200개, 노드별 10,000점으로 상한을 둡니다.
- 64KiB당 1점, 한 영수증 최대 16점으로 큰 패킷·스팸의 이익을 제한합니다.
- 추첨 가중치는 점수 자체가 아니라 제곱근을 사용해 대형 노드의 독점을 완화합니다.
- 직전 확정 블록 해시를 seed로 사용하고 중복 없는 결정론적 추첨을 수행합니다.

보상은 트래픽 바이트를 만든 행위가 아니라 이미 네트워크에서 유효하다고 판정된
고유 메시지를 실제로 다음 피어에 전달한 행위에만 적용해야 합니다. 거래 수수료,
유효 블록/인증서, 요청된 snapshot chunk, 대상이 존재하는 통신 신호만 대상이며
ping, 자기 거래 반복, 거부된 메시지는 제외합니다.

## v0.19.8 포함 범위

- 결정론적 피어 선택 정책과 단위 테스트
- 중계 영수증 중복 제거, 확인자·노드별 상한과 후보 계산
- 제곱근 가중 결정론적 이벤트 추첨
- 운영 기본값 `config/traffic-rewards.json`

## 활성화 전 후속 단계

이번 버전은 합의 안전성을 위해 정책 코어만 포함하고 실제 지급은 아직 켜지
않습니다. 다음 테스트넷 단계에서 다음 순서로 연결합니다.

1. Identify 확장에 서명된 국가/ASN/수용량 광고와 만료 시간을 추가합니다.
2. 관측 RTT와 실제 연결 수로 자기 신고값을 교차 확인합니다.
3. 유효 메시지 수신 피어가 서명한 `RelayReceipt`를 별도 저대역폭 topic으로 전파합니다.
4. 검증자들이 epoch 영수증 root에 합의하고 확정 블록 해시로 당첨자를 계산합니다.
5. 재단 수수료 중 이벤트 풀 적립과 `RelayLotteryReward` 시스템 이벤트 지급을 켭니다.
6. Sybil, 동일 ASN 군집, 영수증 담합, 대량 자기 거래 공격을 100~1,000노드
   시뮬레이션으로 통과한 뒤 운영망에 활성화합니다.

보상 개인키는 기존 `data/reward.key`를 사용하고 PeerId 소유권 등록과 결합합니다.
국가·ASN은 개인정보 원문을 체인에 저장하지 않고 짧은 인증 결과와 만료 시각만
공개합니다.
