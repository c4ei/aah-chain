# 제네시스와 저장 파일

체인은 제네시스 블록이 반드시 필요합니다. 모든 노드는 동일한
`GenesisConfig`와 `genesis_hash`를 가져야 합니다. 운영망 시작 뒤 체인 ID,
초기 배분, 검증자 집합을 바꾸면 서로 다른 체인이 됩니다.

`config/genesis.example.json`의 `31337`은 로컬 개발 전용입니다. 운영 체인
ID는 공개 네트워크와 중복 여부를 확인하고 확정한 뒤 별도 설정으로 배포해야
합니다. EIP-155 raw transaction의 체인 ID가 노드 설정과 다르면 거부됩니다.

크기 정책:

- 개별 블록 기본 상한: 1 MiB
- 블록 세그먼트 파일 상한: 100,000,000 bytes
- 예제 운영값: 99,000,000 bytes

`append_block_segmented`는 다음 블록을 추가했을 때 제한을 넘기기 전에 새
JSONL 파일로 회전합니다. 모바일 장치는 블록 세그먼트를 내려받지 않고 최신
체크포인트·헤더·필요한 상태 증명만 잠깐 동기화하는 구조가 적합합니다.
현재 v0.0.4에는 체크포인트 자료형이 있지만 Merkle 상태 증명 RPC는 후속
작업입니다.
